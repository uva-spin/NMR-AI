Advanced lab · after the nine-step walkthrough

Improve the DNN where it matters:
20% to 30% polarization.

Your job is to optimize prediction accuracy in the signed bands −30% to −20% and +20% to +30%. First use only additional training data and the distribution of that data. Only after finding that limit may you change the DNN by adding one layer.

What makes this different from the walkthrough?

The walkthrough teaches the full pipeline. This lab asks you to make decisions: where to sample, how much data to generate, what metric to optimize, when more data stops helping, whether a slightly more complex DNN improves the focused region, and how much the answer changes with random seed.

Rules for a defensible comparison
RuleWhy it matters
Freeze independent test sets before tuningPrevents choosing the design that happens to flatter one test draw.
Keep preprocessing, optimizer, architecture and seeds fixed during the data-only phaseIsolates the effect of more data and changed sampling distribution.
Report positive and negative bands separatelyA small pooled score can hide a sign-dependent bias.
Keep a guardrail metric outside the target bandShows the cost of specializing the model.
Record rows, configurations, parameters, best epoch and wall timePerformance has a computational and statistical cost.
01

Declare the objective first

Write the target metric before training.

Use the matching report from walkthrough step 4. All commands below assume it exists at local-results/walkthrough/single-site/matching_report.json. Use fresh output paths if your walkthrough folder is different.

Your primary target is regional error in these truth-label bands:

  • Positive target: 0.20 ≤ P < 0.30
  • Negative target: -0.30 ≤ P < -0.20

For each band, report event count, bias, residual width, RMSE, MAE and 95th-percentile absolute error. Use percentage points: multiply fractional-P errors by 100. Your guardrail regions are 0.05 ≤ |P| < 0.10 and 0.40 ≤ |P| < 0.50.

Deliverable

A one-paragraph measurement contract: target P region, primary metric, guardrail bands, allowed changes in each phase, and the fixed test-set names you will use.

02

Do not tune on the final evidence

Generate two fixed focused test sets.

Each test set is tuned to the same experimental signal fits but uses a different random seed. The two signs are generated separately and then combined so the target region has enough statistics.

Run

mkdir -p local-results/advanced/raw local-results/advanced/tests
REPORT=local-results/walkthrough/single-site/matching_report.json

python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min 0.20 --p-max 0.30 \
  --seed 900 --output local-results/advanced/raw/test-a-pos.npz
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min -0.30 --p-max -0.20 \
  --seed 901 --output local-results/advanced/raw/test-a-neg.npz
python tools/combine_datasets.py --output local-results/advanced/tests/focused-test-a.npz \
  local-results/advanced/raw/test-a-pos.npz local-results/advanced/raw/test-a-neg.npz

python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min 0.20 --p-max 0.30 \
  --seed 1900 --output local-results/advanced/raw/test-b-pos.npz
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min -0.30 --p-max -0.20 \
  --seed 1901 --output local-results/advanced/raw/test-b-neg.npz
python tools/combine_datasets.py --output local-results/advanced/tests/focused-test-b.npz \
  local-results/advanced/raw/test-b-pos.npz local-results/advanced/raw/test-b-neg.npz

Do not inspect model performance on these test sets while choosing among training distributions. During design, use validation and a separate development prediction file if you need quick feedback. Use the two fixed tests only for selected candidates.

03

Change the data, not the model

Build broad, focused and mixed training datasets.

The current generator samples uniformly over one interval. Use it deliberately: broad data covers the full working range, focused data covers the region you care about, and mixed data asks whether adding focused rows improves the target band without losing too much elsewhere.

Run

mkdir -p local-results/advanced/data

# Broad baseline distribution.
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 6000 --num-configurations 300 --p-min -0.60 --p-max 0.60 \
  --seed 42 --output local-results/advanced/data/broad-6k.npz

# Focused target distribution, both signs.
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min 0.20 --p-max 0.30 \
  --seed 43 --output local-results/advanced/raw/focus-pos-3k.npz
python tools/generate_matched_data.py --matching-report "$REPORT" \
  --num-samples 3000 --num-configurations 150 --p-min -0.30 --p-max -0.20 \
  --seed 44 --output local-results/advanced/raw/focus-neg-3k.npz
python tools/combine_datasets.py --output local-results/advanced/data/focused-6k.npz \
  local-results/advanced/raw/focus-pos-3k.npz local-results/advanced/raw/focus-neg-3k.npz

# Mixed distribution: broad coverage plus extra target-band rows.
python tools/combine_datasets.py --output local-results/advanced/data/mixed-12k.npz \
  local-results/advanced/data/broad-6k.npz local-results/advanced/data/focused-6k.npz

Interpretation

Focused-only training is not a general estimator. It is a stress test of how much target-band accuracy you can buy by spending all examples there. The mixed dataset tests a more realistic compromise. Keep both because their difference teaches the tradeoff.

04

First comparison: DNN only

Train the same DNN on each training distribution.

Do not change the architecture yet. Use the same optimizer settings and seeds so the comparison is about training data.

Run

mkdir -p local-results/advanced/models
for name in broad-6k focused-6k mixed-12k; do
  python tools/train_model.py \
    --data local-results/advanced/data/${name}.npz \
    --output-dir local-results/advanced/models/dnn-${name} \
    --architecture dnn --epochs 80 --patience 12 \
    --learning-rate 0.0001 --seed 42 --batch-order-seed 42 \
    --device cpu --threads 2 --defer-test
done

If you use a GPU, keep the same device across the compared runs or record the difference. The selected checkpoint still comes from validation loss on that run's training dataset, not from the frozen focused tests.

05

Measure what changed

Evaluate target-band errors on both fixed test sets.

Run predictions on the two frozen focused tests. Then analyze the positive and negative target bands. The helper uses signed bands centered at p0; --p0 0.25 --half-width 0.05 selects 20% to 30%.

Run

mkdir -p local-results/advanced/predictions local-results/advanced/reports
for model in dnn-broad-6k dnn-focused-6k dnn-mixed-12k; do
  for test in focused-test-a focused-test-b; do
    python tools/predict.py \
      --model-dir local-results/advanced/models/${model} \
      --data local-results/advanced/tests/${test}.npz \
      --output local-results/advanced/predictions/${model}-${test}.csv
    python tools/analyze_predictions.py \
      local-results/advanced/predictions/${model}-${test}.csv \
      --p0 0.25 --half-width 0.05 \
      > local-results/advanced/reports/${model}-${test}-pos.json
    python tools/analyze_predictions.py \
      local-results/advanced/predictions/${model}-${test}.csv \
      --p0 -0.25 --half-width 0.05 \
      > local-results/advanced/reports/${model}-${test}-neg.json
  done
done

Read the signed_p_band section in each JSON report. Because the fixed tests are focused, the band count should be large. If the positive and negative results disagree, report them separately rather than averaging the problem away.

Make a compact comparison table

python - <<'PY'
import json
from pathlib import Path
base = Path('local-results/advanced/reports')
for model in ['dnn-broad-6k', 'dnn-focused-6k', 'dnn-mixed-12k']:
    for test in ['focused-test-a', 'focused-test-b']:
        row = [model, test]
        for sign in ['pos', 'neg']:
            band = json.loads((base / f'{model}-{test}-{sign}.json').read_text())['signed_p_band']
            row.append(f"{band['n']} rows, RMSE={band['rmse_percentage_points']:.3f} pp, "
                       f"bias={band['bias_percentage_points']:.3f} pp")
        print(' | '.join(row))
PY
06

How much data is enough?

Build learning curves by adding rows.

Repeat the data-only comparison at several sizes. A useful sequence is 2k, 6k, 12k and 24k. Keep the DNN and training settings fixed. For each size, record target-band RMSE on both test seeds, validation loss, best epoch and training time.

Suggested learning-curve grid
DatasetCompositionQuestion
broad-NUniform −60% to +60%Does more broad coverage improve the target band?
focused-NHalf positive 20-30%, half negative −30% to −20%What is the best target performance when you spend all rows there?
mixed-NBroad rows plus focused rowsWhere is the best target/general tradeoff?

Stop claiming improvement when the two independent test seeds disagree as much as the apparent gain, or when target-band error plateaus while cost continues to grow. That plateau is part of the result, not a failure of the lab.

07

Then change the model

Add one hidden layer to the DNN and compare fairly.

Only after choosing the best data-only distribution should you use the deeper DNN. The new architecture is dnn_extra: a four-hidden-layer dense network with an added intermediate layer. Compare it against the best ordinary dnn trained on the same dataset.

Run

BEST_DATA=local-results/advanced/data/mixed-12k.npz
python tools/train_model.py \
  --data "$BEST_DATA" \
  --output-dir local-results/advanced/models/dnn-extra-mixed-12k \
  --architecture dnn_extra --epochs 80 --patience 12 \
  --learning-rate 0.0001 --seed 42 --batch-order-seed 42 \
  --device cpu --threads 2 --defer-test

Evaluate dnn-extra-mixed-12k on the same two fixed test sets using the commands from section 5. If the extra layer reduces training loss but not target-band test RMSE, report overfitting or optimization limits instead of calling it an improvement.

Fair comparison

The deeper DNN must beat the best data-only DNN, not merely the original broad baseline. Report parameter count from provenance.json, best epoch, training time and both focused test seeds.

08

Statistics are part of the result

Use two generated test sets to estimate metric stability.

For every final candidate, compare the two focused tests side by side. The difference between focused-test-a and focused-test-b is a warning about finite simulated statistics and seed dependence. It is not an experimental uncertainty, but it tells you how much confidence to place in small metric differences.

Then make one guardrail test outside the target band. For example, generate 3,000 rows in 0.40 ≤ |P| < 0.50 and another in 0.05 ≤ |P| < 0.10. If the focused model improves 20-30% but damages 40-50%, your report should say so plainly.

How to discuss limits

Possible limits include insufficient target-band examples, too few independent configurations, validation not aligned with the target metric, DNN capacity, optimization, noise ambiguity, or simulator mismatch. Do not assume more data is the cure until the learning curves show it. Do not assume a deeper DNN is the cure until it beats the best data-only DNN on both focused test seeds.

Final deliverable

Write the investigation report.

  1. Objective: define the signed target bands, metric and guardrails.
  2. Data-only result: compare broad, focused and mixed datasets across at least two sizes.
  3. Learning curve: plot target-band RMSE versus training rows and state where more data stops helping.
  4. Seed stability: show results on both focused test sets and discuss whether differences are meaningful.
  5. Complexity result: compare dnn and dnn_extra on the same best dataset.
  6. Tradeoffs: report target-band improvement and any damage outside the region.
  7. Limits: state what you could not improve using data distribution or one added layer.

The goal is not to make every number smaller. The goal is to learn which knob matters, which result is stable, and where the evidence says to stop.
