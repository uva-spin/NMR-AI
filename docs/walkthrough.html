Begin with step 1 ↓Read the science alongside the code →

This is simulation-based inference of one scalar: vector polarization P. You will use measured sweeps and setup information to constrain a physical simulator, then train a multiscale convolutional neural network (CNN) on newly generated spectra with known P. Experimental P estimates have uncertainty and are not exact training labels. This polarization model returns a number; a denoising autoencoder (DAE) would return a cleaner spectrum. Reducing extraction error still leaves instrument and calibration uncertainties. Read why we use this approach and what its errors mean.

Keep these two operations clear

The three experimental fitters take raw sweeps with their baselines present. They fit the physical circuit and material response together. The UVA-ND3 input already contains a baseline.

Later, the network uses two channels: the raw sweep and the sweep minus a corresponding reference. The generator supplies an independent simulated reference for that step. No TE calibration is required on this learning path. Experimental fit estimates and newly sampled simulator truth labels have different roles.

Use a Bash terminal on Linux, macOS, or Windows with WSL. Run every block from the NMR-AI/ repository directory. Commands go in your terminal; boxes labeled Expected result show what to look for. A CPU can run the tutorial; training uses CUDA when available. Fits may be quiet between completed records, and the two-site fit can take substantially longer than the other steps.

All your results go under local-results/walkthrough/. The fitters, generator, trainer, and predictor require fresh output paths. To repeat the whole exercise, replace that prefix consistently with local-results/walkthrough-2/. To continue an interrupted session, activate the environment again and start at the first unfinished step; completed files remain available.

01

Prepare the workspace

Install the tutorial and check Python.

Use Python 3.10 or newer. If you already have this repository, open a terminal in its directory and start at python3 -m venv .venv. If its environment is already installed, start at activation.

requirements.txt installs PyTorch (torch), NumPy, SciPy, and Matplotlib. For a CPU-only or GPU-specific build, use the official PyTorch installation selector: choose Stable, Pip, Python, your OS (Linux inside WSL), and your compute platform. Run the selected command after activating .venv and before the requirements command below. Replace pip or pip3 with python -m pip to install into the active environment.

lineshape-data.npz stores the arrays. lineshape-data.json records the seed configurations, coverage settings, units, hashes, and limitations. The two feature channels are raw and raw-minus-reference; subtraction happens in float64 before conversion to float32. Clean simulator signals are diagnostic arrays and do not enter training.

The sampled ranges are controlled robustness choices. The white-noise setting uses a residual-based high-frequency proxy; it does not reproduce every correlated residual seen above. These five measured sources do not establish a population distribution. Read the generator coverage and noise assumptions.

Choose coverage before increasing the event count

This command samples P uniformly. Near zero, the response is weaker and the intrinsic branch weights become more equal, so a small imbalance can be harder to distinguish from noise or amplitude changes. Inspect validation errors and counts on both sides of zero. Extra low-|P| examples may help, provided they span supported noise and setup conditions and leave enough coverage elsewhere.

--num-samples adds events and --num-configurations sets the number of simulated configurations. Neither adds measured sources. --p-min and --p-max change the uniform range; they do not create a non-uniform mixture. Try the interactive sampling example and read the training-data design guide before extending the generator or weighting training rows. Preserve the current exercise for a reproducible starting point.

Keep these together; the predictor uses them. The published run selected epoch 6 and stopped after 18 epochs. The stopping epoch and final decimals can differ with library versions, device, and numerical fit differences.

The learned branch uses 5-, 15- and 31-bin filters, residual blocks and internal average pooling from 500 to 250 to 125 positions. Global mean, maximum and SD pooling feed a correction head; a second branch fits a ridge estimate from 25 amplitude and shape summaries of all 500 positions. Their sum predicts P. Follow each layer and its purpose, then read why the summaries are included.

This step uses raw/reference recorded units without an area-calibration input. The separate TE-area benchmark supplies calibrated per-bin area contributions to the same architecture. TE names its chosen reference, not a restriction to TE-scale polarization. Read about known-P references and Boltzmann spin equilibrium.

Read how the convolution filters and physical summaries work. Splitting 2,000 events at random would mix descendants of the same measured seed across partitions; the saved source grouping avoids that leakage.

Understand what one epoch does

The default batch size is 128: 1,200 training rows give 10 updates per epoch, including a smaller final batch. Each update computes scaled mean squared error, backpropagates, clips the gradient norm, and updates the neural weights with AdamW. The 26 ridge coefficients were fitted first on training rows and remain frozen. Validation evaluates the resulting model without updating its weights.

The learning-rate scheduler can reduce the step size when validation improvement stalls. Separately, --patience 12 stops after 12 successive epochs without a new best validation loss; --epochs 80 is the maximum. More epochs reuse the same examples. They do not provide new training data.

How much data should I generate for my own model?

There is no dependable examples-per-weight ratio. This model has 82,365 parameters optimized during neural training plus 26 fitted ridge coefficients, yet the required dataset depends on noise, the range of physical conditions, model structure, and the error target. The 2,000-event exercise demonstrates the workflow; it does not establish sufficient coverage for another experiment.

Compare nested training sizes, such as 1,200, 2,400, 4,800 and 9,600 rows when available, using fixed validation inputs and source groups. Refit preprocessing and weights using each training subset only. Record pooled and signed low-|P| errors, independent group counts, optimizer updates, and variation across seeds. Study adding events within existing setups separately from adding independent setups. The current CLI does not automate this fixed-validation study.

Low training error with worse validation error motivates more independent coverage or stronger regularization. High errors in both partitions also warrant checking inputs, optimization and model capacity. If extra rows stop helping, investigate the limiting factor before simply increasing the count. Compare errors in percentage points, since normalized target scales can differ between runs. Keep final testing for the frozen design. Read the dataset-size lesson and study protocol.

09

Use the saved model and inspect its errors

Make 400 predictions, then read the error report.

The predictor reloads your saved model and preprocessing. Use the same NPZ and --partition test so it checks the dataset hash and evaluates only the held-out rows. Predictions and labels are fractional P: 0.05 means 5% polarization.

Run

python tools/predict.py \
  --model-dir local-results/walkthrough/lineshape-model \
  --data local-results/walkthrough/lineshape-data.npz --partition test \
  --output local-results/walkthrough/test-predictions.csv
python tools/analyze_predictions.py local-results/walkthrough/test-predictions.csv \
  --p0 0.05 --half-width 0.005

Expected result

Saved 400 predictions to local-results/walkthrough/test-predictions.csv, then a JSON error report. The CSV contains P_true, P_pred, P_residual, and the configuration/source identifiers. Open it in a text editor or spreadsheet.

Read pooled.n first: it should be 400. Then inspect bias_percentage_points, width_percentage_points, and rmse_percentage_points. The published source-held-out run has an RMSE of about 6.37 percentage points; this is a comparison value, not a pass threshold for your environment.

The signed_p_band section restricts truth to 4.5% ≤ P < 5.5%. Check its count before interpreting a local error. A small band count gives limited evidence, even with many pooled events.

The residual convention is P_true − P_pred. Positive bias means underprediction, and RMSE² = bias² + width² with population SD. Percentage-point error is 100 times fractional-P error. These are simulated recovery errors for one held-out source group, not measured experimental polarization accuracy.

Choose the lowest nonzero polarization magnitude you need before selecting a model, and quantify errors near that scale as well as over the full range. A pooled score can hide the region of interest. The interactive polarization-error comparison shows absolute and relative RMS, both signs, and local event/group counts using the separate TE-area benchmark. Its scores do not transfer to this raw/reference network. At zero, use absolute error; relative error is undefined.

If relative RMS persistently fails to improve as |P| grows under comparable fixed-noise conditions, investigate possible underperformance. Check counts, coverage, convergence and model limitations; test whether more independent training data help on fixed validation arrays. The plateau diagnostic explains the comparisons and why the curve alone cannot identify the remedy or establish a noise limit.
